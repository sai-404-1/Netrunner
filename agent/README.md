# NetRunner endpoint-агент

Постоянное WebSocket-соединение «компьютер → NetRunner» для статусов и телеметрии.
Устанавливается по SSH модулем `agent_provision` (в веб-панели: Модули →
«Установка endpoint-агента», admin_only). Это отдельная от обычного SSH-управления
подсистема — SSH остаётся каналом исполнения команд/модулей, WebSocket-агент
никогда не исполняет ничего присланного сервером.

## Устройство

- `netrunner_agent.py` — сам агент: asyncio + пакет `websockets`, звонит на сервер
  исходящим соединением (работает через NAT, на хосте не нужно открывать порты).
  Запускается через systemd при загрузке хоста и держит соединение постоянно, с
  автопереподключением при обрыве (`RECONNECT_DELAY_SEC = 15`).
- `netrunner-agent.service` — systemd-юнит: отдельный непривилегированный
  пользователь `netrunner-svc`, `ProtectSystem=strict`/`ProtectHome=true`/
  `NoNewPrivileges=true`, `Restart=always`.
- Конфиг на хосте — `/etc/netrunner-agent/config.json` (`host_id`, `token`,
  `server_ws_url`), пишется модулем `agent_provision` при установке.

## Протокол

Один хендшейк + два типа сообщений, конверт всегда одинаковый
(`{"type": ..., "hostname": ..., "ts": ..., ...}`):

1. `hello` — `{"type": "hello", "host_id": N, "token": "..."}`, отправляется сразу
   после установления соединения. Сервер проверяет токен
   (`AgentService.verify_token`) и либо принимает соединение, либо закрывает его
   (коды 4001/4003).
2. `online` — отправляется один раз сразу после успешного `hello`. Поскольку агент
   стартует по systemd при загрузке ОС, первый `online` для сервера и есть сигнал
   «компьютер включился».
3. `heartbeat` — раз в `HEARTBEAT_INTERVAL_SEC` (60с), пока соединение живо:
   `hostname`, `uptime_seconds`, `ts`.

**Направление компьютер → сервер — только статусы, никогда команды на
исполнение.** Направление сервер → агент — тоже report-only: сервер не шлёт агенту
ничего, кроме закрытия соединения при невалидном токене; агент читает входящие
сообщения только чтобы вовремя заметить обрыв связи и **никогда** не
интерпретирует их содержимое как команду (структурное ограничение, не просто
политика — в коде агента попросту нет пути от `ws.recv()` к исполнению чего-либо).

Сервер журналирует любой присланный `type` в таблицу `host_events` как есть
(`services/agent_service.py::record_event`) — добавление нового типа статуса в
будущем **не требует** менять код сервера, только добавить вызов
`send_status(ws, "новый_тип", ...)` в агенте в нужном месте.

## Расширение на будущее

`send_status()` в `netrunner_agent.py` — общая точка отправки статуса любого типа.
Примеры того, что можно добавить без изменения протокола/сервера, когда появится
конкретика (пока не реализовано, только точка расширения):

- `shutdown` — через `ExecStopPost=` в systemd-юните (нужен отдельный синхронный
  скрипт-однострел, т.к. `ExecStopPost` не ждёт долгоживущий asyncio-процесс);
- события входа/выхода пользователя, смены сети и т.п. — отдельные хуки,
  вызывающие `send_status()` с новым `type`.

## Два независимых секрета

- **SSH-ключ сервисного пользователя** (`netrunner-svc`, ED25519) — канал
  восстановления через уже существующий обычный SSH, если токен/агент когда-нибудь
  потребуется перевыпустить. Обычный SSH-доступ хоста (под исходным
  пользователем) при установке агента **не отключается** — чтобы не было лок-аута.
- **Bearer-токен** — аутентифицирует только само WS-соединение агента.

Компрометация одного секрета не вскрывает другой. Оба хранятся на сервере в
зашифрованном виде (`services/secrets.py`), в открытом виде токен виден только
один раз — в момент установки (модуль `agent_provision`).

## Важно про адрес сервера

Порт бэкенда (8000) не экспонирован из Docker-контейнера — агент, в отличие от
браузера, не может подставить относительный путь, поэтому `server_ws_url` должен
идти через порт Next.js (3001 в Docker) и префикс `/api/python/`, который
проксируется на бэкенд:

```
ws://SERVER_IP:3001/api/python/agent/ws
```

а не `ws://SERVER_IP:8000/agent/ws` напрямую.

## Статус

Не проверялся против живого хоста в этой сессии (нет доступа к тестовой машине).
Проверено: `python3 -m py_compile` на всех файлах бэкенда, синтаксис агента.
