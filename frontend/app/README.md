# frontend/app

Маршруты Next.js (App Router). Каждая папка `*/page.tsx` — отдельная страница панели;
большинство — клиентские компоненты (`"use client"`), которые ходят на бэкенд через
`lib/api-client.ts` с куки-аутентификацией.

## Каркас
- `layout.tsx` — корневой layout (провайдеры, шрифты; инлайн-скрипт темы до отрисовки,
  `<html suppressHydrationWarning>`).
- `page.tsx` — главная страница **«Обзор»** (дашборд: сводка по хостам/задачам/отчётам).

## Страницы
- `hosts/page.tsx` — **Хосты**: реестр узлов, добавление/редактирование, проверка
  доступности, перепривязка SSH-ключа, режим «Доска». Блок с **вкладками
  «Кабинеты» / «Хосты»** (поиск/фильтр — строкой). Под строкой инструментов — **блок
  запуска задачи** (`hosts/RunPanel.tsx`, перенесён со страницы «Запуск задачи»):
  выбор модуля, целью становится выбранный в списке хост/кабинет (кнопка «Выбрать» →
  подсветка списка → клик по цели). Тип цели следует за активной вкладкой. Выбранный
  фильтр/вкладка переживают уход на профиль хоста (localStorage `netrunner_hosts_view`).
  Для роли `teacher` кнопка «Добавить хост» скрыта, список — только его кабинеты
  (фильтрация на бэкенде); редактирование хоста и терминал доступны, удаление — нет.
- `modules/page.tsx` — **Модули**: встроенные и пользовательские модули в одном блоке с
  **вкладками**; загрузка/включение, схемы. Для роли `teacher` панель «Добавить модуль» и
  кнопка удаления скрыты (запуск на своих хостах — можно).
- `run/page.tsx` — **Запуск задачи**: выбор модуля и цели, аргументы, **живой прогресс по
  хостам** (в очереди / выполняется / готово / ошибка); для модуля `file_distribute` —
  менеджер файлов (`FileManager`). Из сайдбара пункт убран — блок запуска перенесён на
  «Хосты» (`hosts/RunPanel.tsx`); страница остаётся доступной по URL.
- `history/page.tsx` — **История**: **вкладки «История» / «Отчёты»** (отчёты — через
  `components/ReportsView.tsx`). Для роли `teacher` и лента, и отчёты отфильтрованы
  бэкендом по его кабинетам (видит запуски, где участвовал хотя бы один его хост).
- `scheduled/page.tsx` — **Планировщик**: запланированные задачи (Активные/Не активные),
  каждая запускает **сценарий**. Создание/редактирование — модал `TaskFormModal.tsx`
  (условие «по времени»/«когда будет в сети»; в режиме по времени — recurring-расписание:
  дни недели + окно «С…До» + интервал, либо «Запустить один раз» с конкретным моментом;
  название/описание, цель, сценарий). Таблица `TaskTable.tsx` показывает условие через
  `lib/schedule-utils.ts::scheduleLabel` и переключает активность задачи.
- `inventory/page.tsx` — **Инвентаризация**: снимки оборудования/ОС по хостам.
- `reports/page.tsx` — рендерит `ReportsView` (маршрут оставлен; из сайдбара убран,
  контент — во вкладке «История»).
- `scenarios/page.tsx` — **Сценарии**: цепочки модулей; запуск **в фоне** с живым
  опросом — панель «Выполнение» подсвечивает активный шаг/модуль и статус каждого шага.
  Для роли `teacher` кнопка удаления сценария скрыта (сценарии общие; запуск на своих
  хостах — можно).
- `keys/page.tsx` — **Ключи**: SSH-ключи (загрузка, генерация, ключ по умолчанию).
- `account/page.tsx` — **Профиль**: смена своего имени/пароля, переключатель темы,
  привязка Telegram и список доверенных устройств (2FA: отозвать / доверять бессрочно);
  внизу — «Выйти из аккаунта».
- `admin/page.tsx` — **Администрирование**: страница разбита на **вкладки** (папка
  `admin/tabs/`): «Пользователи» (`UsersTab`), «Агент» (`AgentTab`), «База данных»
  (`DatabaseTab`), «SSH-ключи» (`SshKeysTab`). Вкладки рендерятся всегда, неактивные
  скрыты через `hidden` (не перемонтируются — стейт/запросы не сбрасываются при
  переключении). Роли user/teacher/**admin** назначаются через селект (роль `admin` даёт
  те же права, что бутстрап-аккаунт admin/admin). У каждого пользователя кнопки «Доступ к
  кабинетам» (`user_group_access`, выдача кабинетов преподавателю — подпись в модалке
  зависит от роли) и «Доступ к модулям». Блоки «Обновление»/Telegram здесь не рендерятся.
- `update/page.tsx` — рендерит `UpdatePanel` (отдельный, не связанный со страницей
  администрирования маршрут; из сайдбара убран).
- `login/page.tsx` — форма входа; двухшаговая при 2FA (пароль → одноразовый код из
  Telegram + чекбокс «доверять устройству 1 час»).

## Серверные роуты
- `api/login/route.ts` — логин: проксирует на бэкенд, ставит httpOnly-куки `netrunner_token`
  (только после полной аутентификации) и долгоживущую `netrunner_device` (id устройства
  для 2FA). При `mfa_required` токен не выдаётся — возвращает челлендж.
- `api/login/verify/route.ts` — второй шаг 2FA: шлёт код + `device_id` на бэкенд, при успехе
  ставит `netrunner_token`.
- `api/logout/route.ts` — логаут: сбрасывает куки.
